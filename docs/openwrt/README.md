# Twitch Drops Miner on OpenWrt

This branch turns [TwitchDropsMiner](https://github.com/DevilXD/TwitchDropsMiner) into a
headless service that runs 24/7 on an OpenWrt router, managed through LuCI.

The original application is a Tkinter desktop app: it requires a display server and
Tkinter before it even parses its command line. This port adds a headless UI
replacement, keeps every piece of the mining logic untouched, and ships everything as
three OpenWrt packages.

**Status:** builds and runs on ImmortalWrt/OpenWrt `armsr/armv8` (aarch64, apk),
verified 2026-10. The only blocked feature is login — see
[Authentication](#authentication).

---

## Packages

| Package | Contents |
|---|---|
| `twitch-drops-miner` | The application in headless mode, its python dependencies (vendored wheels), a procd init script and the UCI configuration |
| `luci-app-twitchdropsminer` | LuCI pages: overview (status/progress/channels/logs), login (cookie upload), settings |
| `luci-i18n-twitchdropsminer-zh-cn` | Simplified Chinese translation (generated by `luci.mk` from `po/`) |

The packages are built for both `25.12.x` (apk, requires OpenWrt 25.12+) and `24.10.x`
(ipk) via [openwrt/gh-action-sdk](https://github.com/openwrt/gh-action-sdk) — see
`.github/workflows/openwrt.yml`.

## Installation

1. Download the package set for your architecture from the
   [Actions](../../actions) page (artifacts of the latest successful run), or build
   them yourself (see [Building](#building)).
2. Copy them to the router and install:

```sh
scp *.apk root@192.168.1.1:/tmp/
ssh root@192.168.1.1
apk add --allow-untrusted /tmp/twitch-drops-miner-*.apk \
    /tmp/luci-app-twitchdropsminer-*.apk \
    /tmp/luci-i18n-twitchdropsminer-zh-cn-*.apk
/etc/init.d/twitchdropsminer enable
/etc/init.d/twitchdropsminer start
```

CI-built packages are unsigned, hence `--allow-untrusted`. On 24.10 use
`opkg install` with the `.ipk` files instead.

3. Open LuCI → **Services → Twitch Drops Miner**.

The LuCI app depends on the `luci-base` and `luci-compat`-era runtime that ships with
any standard OpenWrt image; nothing else is pulled in.

## Authentication

Twitch has disabled the OAuth device code flow the application used
(upstream [#1165](https://github.com/DevilXD/TwitchDropsMiner/issues/1165); the
maintainer is reworking login around browser automation, which cannot run on a router).
The miner therefore signs in with a **saved session**, exactly like a desktop install
that was logged in once:

1. On a PC, run the miner and complete the Twitch login (or use any other method that
   produces a valid `cookies.jar`).
2. On the router: **LuCI → Services → Twitch Drops Miner → Login**, and upload that
   `cookies.jar`. The file is imported into the miner's data directory and the service
   is restarted automatically.
3. The overview page then shows the login state, the channel list and mining progress.

A `settings.json` (priority/exclude lists, mode, proxy…) can be uploaded on the same
page; it is optional — everything in it can also be configured on the Settings page.

## Configuration

UCI config `/etc/config/twitchdropsminer` (also editable on the LuCI Settings page):

| Option | Default | Meaning |
|---|---|---|
| `enabled` | `1` | Start with the system |
| `data_dir` | `/etc/twitchdropsminer` | Where `cookies.jar`, `settings.json` and the log live |
| `log_level` | `2` | 0=error 1=warning 2=info 3=debug (calls) 4=debug (everything) |
| `connection_quality` | `1` | 1 = best connection … 6 = worst (request timeouts) |
| `priority_mode` | `0` | 0=priority list only 1=ending soonest 2=low availability first |
| `available_drops_check` | `0` | Check that a channel can earn drops before switching |
| `proxy` | *(empty)* | HTTP proxy URL |
| `priority` (list) | *(empty)* | Games to mine first, in order |
| `exclude` (list) | *(empty)* | Games to never mine |

The init script regenerates `settings.json` from UCI on every start (including the
`__type` wrappers the miner expects), so the two never drift apart. Saving on the LuCI
Settings page restarts the service.

Runtime files:

| Path | Purpose |
|---|---|
| `/tmp/twitchdropsminer.log` | Live log (`logread` shows the same output); the data dir's `log.txt` is a symlink to it, to avoid flash wear |
| `/tmp/twitchdropsminer.status.json` | Live JSON status written every 2s, consumed by the LuCI overview page |
| `/usr/lib/twitchdropsminer/` | Application + vendored dependencies |
| `/var/run/…` | — |

## Headless mode

`main.py --headless` runs the miner without Tkinter, a display or a tray:

- replaces `GUIManager` with a headless UI that implements the interface contract the
  core awaits (close handling, login, channel selection, progress timing),
- prints everything to stdout (captured by procd → syslog),
- exits with a non-zero status on fatal errors instead of waiting for the user to close
  a window, so procd can restart it (limited to 5 restarts per hour),
- keeps persistent files in `TDM_DATA_DIR` (set by the init script from `data_dir`),
- writes the status file consumed by LuCI.

Data files default to the app directory when `TDM_DATA_DIR` is not set, so upstream's
desktop behaviour is unchanged.

## Building

Cloud (recommended) — push to the `openwrt` branch, or run the
**Build OpenWrt packages** workflow manually; artifacts contain the `.apk`/`.ipk` files.

Locally with the SDK container:

```sh
docker run --rm -it -v "$PWD:/feed" openwrt/sdk:aarch64_generic-25.12.3
# inside: install the feed, then build the packages
./scripts/feeds update -a && ./scripts/feeds install -a -p luci
echo "src-link twitchdropsminer /feed" >> feeds.conf
./scripts/feeds update -a && ./scripts/feeds install -a -p twitchdropsminer
make package/twitch-drops-miner/compile V=s
make package/luci-app-twitchdropsminer/compile V=s
```

The python dependencies are vendored as musllinux wheels in
`twitch-drops-miner/files/wheels/` (the OpenWrt feeds are missing the aiohttp
dependency chain); regenerate them with `twitch-drops-miner/fetch-wheels.sh` when the
target python version changes.

> **When bumping `PKG_SOURCE_VERSION`** (the pinned app commit), update
> `PKG_MIRROR_HASH` too, or the build fails with `Package HASH check failed`. The
> correct value is printed by `make package/twitch-drops-miner/check V=s`.

## Keeping the fork in sync with upstream

`master` mirrors upstream, `openwrt` carries the port on top of it:

```sh
git fetch upstream
git switch master && git merge --ff-only upstream/master && git push origin master
git switch openwrt && git rebase master && git push --force-with-lease origin openwrt
```

After a rebase that touches the application sources (anything the package ships),
bump `PKG_SOURCE_VERSION` and `PKG_MIRROR_HASH` in `twitch-drops-miner/Makefile`, or
the package would keep shipping the old sources.
